# Магазин приложений

Репозиторий с двумя вещами: магазин (`store/`) и приложениями, которые он раздаёт.
Сервера нет — каталог и APK лежат в этом же репозитории.

**Скачать магазин:**
https://github.com/i77391166-netizen/apps/releases/download/latest/store-debug.apk

**Каталог:** `catalog.json` (магазин читает его с raw.githubusercontent.com).
**APK:** релиз с тегом `latest`, файлы `store-debug.apk` и `music-debug.apk`.

## Как это работает

- Магазин читает `catalog.json`: пакет, название, описание, ссылка на APK, `versionCode`, версия.
- Сверяет с установленным на телефоне: нет — «Установить», старее — «Обновить», актуально — «Открыть».
- Качает APK в кэш и отдаёт системному установщику через свой `ContentProvider`
  (`file://` на Android 7+ запрещён).
- Долгое нажатие на карточку — удалить приложение.

Тихих обновлений не бывает: Android всегда показывает свой экран установки,
а магазину один раз надо разрешить «Установка неизвестных приложений».

## Подпись

Все сборки подписываются одним ключом `signing/ham.jks` (alias `ham`, пароль `hamham`).
Workflow создаёт его при первом запуске и коммитит в репозиторий.
Без постоянного ключа обновление поверх старой версии не ставится — Android ругается
на несовпадение подписи. Ключ лежит в открытом репозитории, так что подписать им что-то
может любой: для личных сборок нормально, для Google Play — нет.

## Добавить приложение

1. Положить модуль в корень (как `music/`), добавить его в `settings.gradle`.
2. В `app/build.gradle` указать `applicationId`, `versionCode`, `versionName`.
3. Собрать, положить APK в релиз `latest` (workflow делает это сам, если APK есть в `files`).
4. Дописать запись в `catalog.json`.

## Сборка

Пуш в `main` → GitHub Actions собирает все модули (`gradle assembleDebug`),
перезаписывает релиз `latest` и артефакт `apps-apk`.
